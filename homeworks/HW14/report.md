# HW14 – эмбеддинги, FAISS, оценка retrieval и mini-RAG по базе знаний

## 1. Кратко: что сделано

- Какая база знаний использовалась и почему.  
Использовалась база знаний - документация GNU Autotools. В частности, был взят набор страниц документации и обработан, чтобы удовлетворить условиям (см. `data`).
- Как был организован чанкинг документов.  
Документы разбивались на чанки по словам: chunk_size=40, overlap=12.
- Какая embedding-модель или какой способ векторизации использовался.  
Использовалась модель sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 через бэкенд SentenceTransformersBackend.
- Что показала базовая проверка retrieval.  
На 8 контрольных запросах при top_k=3: mean_hit@3 = 1.0, mean_recall@3 = 0.85, mean_MRR@3 = 0.94. Retrieval корректно находил релевантные документы в большинстве случаев.
- Что изменилось после обновления базы знаний.  
После добавления 2 новых документов и переиндексации, запросы по теме "dependency tracking" стали возвращать правильные источники 
- Как сработал mini-RAG.  
Mini-RAG формировал контекст из top-3 чанков, затем выбирал 2 наиболее релевантных предложения через TF-IDF. На 5 тестовых вопросах mean_rag_keyword_recall = 0.45 против 0.32 у baseline без retrieval.

В качестве базового retrieval-конвейера для подобной задачи я бы оставил: чанкинг с перекрытием 25-30%, эмбеддинги через multilingual MiniLM, индекс FAISS IndexFlatIP с косинусным сходством и top_k=3.
